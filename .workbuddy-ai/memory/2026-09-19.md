# 2026-09-19 — RentFlow Africa : fondation durcie et shell web complété

## Contexte

Reprise du dépôt `immoNova` (produit : **RentFlow Africa**, SaaS multi-tenant de gestion
locative pour l'Afrique francophone). La documentation et un squelette partiel existaient, mais
le dépôt **ne compilait pas** et l'application web n'avait pas de point d'entrée.

## Diagnostic initial (constats)

- `npm run typecheck` échouait :
  - `apps/api/src/common/logger.ts` — `import pinoHttp from 'pino-http'` non appelable en ESM/NodeNext.
  - `apps/api/src/middleware/permissions.ts` — `@rentflow/shared` introuvable (`dist` jamais construit).
- `apps/web` était **non exécutable** : `index.html` référençait `/src/main.tsx` qui n'existait pas.
  Aucun `App.tsx`, aucun `index.css` (les variables CSS utilisées par Tailwind n'étaient pas définies),
  aucun routeur, aucun layout, aucune page.
- Test API `rejects an unapproved origin` en échec : CORS configuré avec une origine en chaîne,
  ce qui envoie `Access-Control-Allow-Origin` à toutes les requêtes.
- `npm test` échouait (aucun fichier de test dans `shared` et `web`).
- Rate limiters dupliqués (`middleware/rate-limiters.ts` vs `middleware/security.ts`).

## Pièges rencontrés (à retenir)

- **ESM + `pino-http`** : utiliser `import { pinoHttp } from 'pino-http'` (pas d'import par défaut).
- **Monorepo npm workspaces** : `npm run build --workspaces` exécute `apps/*` avant `packages/*` ;
  un paquet partagé consommé via `dist` doit être construit avant → hooks `pre*` dans le root.
- **`cors` avec `origin: string`** envoie l'en-tête ACAO à tout le monde ; utiliser un tableau.
- **Vitest sur cette machine** : très lent au premier démarrage ; un cold start peut dépasser le
  timeout RPC (`/@vite/env`). Relancer ; les timeouts de config ont été augmentés.
- Les commandes longues (build ~8 min) doivent tourner en arrière-plan.

### Erreurs rencontrées et corrigées

- **`pino-pretty`** : install interminable et non déclarée → transport retiré du logger
  (démarrage sans dépendance), `pino-pretty` déclaré en devDependency et exposé via
  `npm run api:dev:pretty` (pipe). Le chemin par défaut ne peut plus échouer.
- **`genReqId`** : `req.requestId` non typé sur `IncomingMessage` → cast explicite.
- **`buttonVariants('outline')`** : variante inexistante (primary|secondary|ghost|danger) → `secondary`.
- **Apostrophe** : message `d'exemple` (ASCII) vs test `/valeur d’exemple/` (typographique U+2019)
  → harmonisé sur la typographie française dans `env.ts`. **Piège à retenir : le projet utilise
  l'apostrophe typographique dans tout le texte français.**
- `initials` importé puis shadowé par une variable locale → renommé `userInitials`.
- **`COOKIE_DOMAIN=` (vide) empêchait le démarrage** — bug réel découvert **uniquement en lançant
  le serveur**, pas par les tests. Une variable optionnelle laissée vide arrive comme chaîne vide,
  pas comme `undefined` : `.optional()` ne s'applique donc pas et `.min(1)` échoue. Corrigé par un
  `optionalStringSchema` qui normalise `''`/espaces → `undefined`. Trois tests ajoutés.
  **Leçon : toujours démarrer réellement le serveur, les tests unitaires ne couvrent pas le
  chargement d'un vrai `.env`.**
- **`fullUrl()`** : `exactOptionalPropertyTypes` refuse `IncomingMessage` (où `url` est
  `string | undefined`) pour un paramètre `{ url?: string }` → signature en
  `{ url?: string | undefined }`. Détecté par le typecheck, **pas** par les tests (vitest
  transpile sans vérifier les types).
- `customSuccessMessage` utilisait `req.url`, amputé du préfixe de montage par Express
  (`/live` au lieu de `/api/health/live`) → `req.originalUrl` via un helper `fullUrl()`.
- L'erreur Mongoose complète sérialisée déversait plusieurs ko de topologie dans les logs →
  journalisation d'un objet concis (`target`, `reason`).
